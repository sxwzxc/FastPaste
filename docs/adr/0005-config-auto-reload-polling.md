# 配置自动重载采用轮询而非文件监视库

自动重载不引入 `notify` 等文件监视依赖，而是复用剪贴板轮询线程，节流至约每秒一次读取 `config.toml` 并计算内容哈希。不依赖 mtime/size 做预检——粗粒度时间戳（FAT 可达 2s）会漏检同尺寸的快速连写；配置文件极小，整读开销可忽略。理由与 ADR-0002 同谱系：配置变更频率极低、亚秒级延迟无感知；同时规避 Windows 上单文件监视被编辑器原子替换（临时文件+rename）打断的坑与保存事件风暴。连续两次采样哈希一致才尝试加载，以消化原地写入的瞬时中间态；触发本身不改基线，基线的唯一记账入口是管线结算——成功应用、或自动路径裁定拒绝时以落盘内容复采，保证同一内容结算后不再触发（校验失败也结算，避免对坏配置反复重试）；结算前的重复触发由主线程的请求标志位合并。检测在轮询线程完成，实际重载统一汇入主线程事件循环执行，与手动重载共用同一条校验→应用管线。
